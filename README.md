# Marshall JCM800 — STM32N6

Физическая цифровая модель **Marshall JCM800 2203 Master Volume, 100 Вт, EL34**
по двум заводским листам **24 апреля 1981 года**. Самостоятельный проект;
соседний Big Muff развивается отдельно.

**Статус на 2026-09-11: инженерная макромодель принята для численного сокращения;
физическая аттестация реального усилителя остаётся открытой.**
Для Dempwolf RSD-1 + Reefman выполнены установление питания, баланс, исправление
RGI/ёмкостей, сгущение атак и восстановление. Точное линейное сокращение
98 → 39 неизвестных Ньютона проверено на запуске, атаках и восстановлении.
Сокращённая сборка нелинейностей ускорила эти режимы в **2,06–2,18 раза на Python/ПК**
при побитовом совпадении всех состояний с предыдущим Schur-решателем.
Первая матрица независимых Gain/Master/Tone/Presence/NFB также прошла сравнение
с полной MNA; DI и длинное восстановление новых положений остаются следующим этапом.
Первые 20 мс сухого гитарного аккорда проверены в пяти режимах; вычислительная
эквивалентность подтверждена, причины глубокого физического перегруза исследуются.
Диагностическая абляция показала основной источник раннего перегруза: прежние
Gain/Master=0,5 являются электрической долей, тогда как заводская схема требует
LOG-характеристику. Добавлена отдельная механическая шкала 0–10 с параметризованным
10%-м midpoint; точная кривая конкретных деталей остаётся задачей измерения.
Полный 250-мс аккорд и 500 мс восстановления рассчитаны в четырёх положениях;
WAV сохранены. Звуковой выход затух, но тяжёлые режимы ещё не полностью вернули
внутренние состояния питания и фазоинвертора к синхронному холостому режиму.
Экранная диагностика исправлена: тепловой лимит Philips сравнивается со средней
и скользящей мощностью, а не с одиночным микросекундным пиком.
Отдельная реактивная гипотеза Brit 4×12 проверена на полном четырёхсекундном
аккорде: она заметно меняет форму выхода, включая сустейн, но её высота и Q
резонанса пока не опираются на измерение конкретного кабинета.
Начат перенос вычислительного ядра в C: float64-законы ECC83/EL34 совпали с
Python до машинной точности, а режим токов отделён от более дорогого расчёта
Jacobian. Полный C-решатель и аппаратный замер тактов ещё не выполнены.

## Что реализовано

Общий решатель MNA float64 охватывает весь тракт:
High Input → V1b → Gain → V1a → V2a → V2b → Tone → Master → V3
→ четыре EL34 → выходной трансформатор → нагрузка 16 Ом.
Presence, обратная связь от отвода 4 Ом и общие цепи питания решаются совместно.
Полная версия с подробными лампами содержит **84 узла и 98 неизвестных**,
с прежним Koren — 90 узлов и 104 неизвестных. Она включает сетевой мост, bias,
связанные обмотки питания/накала и нагруженные отводы выходного трансформатора.

Текущий инженерный набор — Dempwolf RSD-1 + Reefman с RGI+Rs=2001 Ом
и паспортными ёмкостями. Прежний Koren сохранён для воспроизведения истории;
функция `build()` по умолчанию выбирает его, поэтому новые опыты явно задают
`tube_set="detailed:RSD-1"`. Трансформаторы линейные, магнитные и диодные
параметры предварительные. Добавлена отдельная параметрическая электрическая
гипотеза Brit 4×12; она ещё не заменяет измеренный кабинетный эталон. Магнитное
насыщение, тепловой прогрев, акустический IR и прошивка STM32N6 пока отсутствуют.

В отдельной точке Philips экранный ток EL34 по Reefman составляет **12,32 мА**
против прежних **5,76 мА**, при табличных **14,9 мА**. На напряжениях прежнего
покоя он составляет 2,04 мА вместо нуля. Это проверка закона при заданных
напряжениях, а не новая рабочая точка всего усилителя.

Численная сверка новых законов прошла, но физическая аттестация не завершена:
есть расхождения с Philips, ограничение ECC83 при малом анодном напряжении,
непроверенные крайние режимы EL34 и положительный сеточный ток EL34.
Мощность 264–275 Вт в прежнем опыте относится к короткой атаке с разрядом
накопителей; длительная мощность усилителя этим не установлена.

## Ближайшие работы

1. Расширить проверку на DI, положения ручек, ООС и восстановление,
   сохраняя сопоставление с полной MNA на одинаковой временной сетке.

## Воспроизведение

Из корня проекта на macOS/Linux, с ngspice в PATH:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python reference/fetch_tube_validation.py
.venv/bin/python simulation/run_tube_validation.py
```

Для первой распаковки авторского MSI требуется 7zz/7z; Windows-программа из него
не запускается. На текущей машине установлены `.venv`, ngspice 47 и 7zz.
На Windows можно использовать `.venv\Scripts\python.exe` из локального окружения.

Прежние опыты усилителя запускаются отдельно:

```sh
.venv/bin/python simulation/run_reference.py
.venv/bin/python simulation/run_full_mna.py
.venv/bin/python simulation/run_settling.py
```

Эти программы перезаписывают свои отчёты. `--quick` у первых двух программ
оставляет только сокращённый набор опытов. Старые сырые состояния усилителя
на этой машине отсутствуют; первое установление потребуется выполнить заново.
Первичная проверка Koren сохранена в `simulation/validate_tubes.py` и
[старом отчёте](simulation/experiments/tube_validation/report.md).
